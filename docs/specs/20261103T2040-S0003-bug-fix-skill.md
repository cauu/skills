## 1. Requirement Details

### Background

修 bug 时常见的问题：用户说有 bug，agent 没复现就改；改动里夹带“可能有用”的防御代码；修完只跑单元测试。

### Scope

新增可分发 skill `skills/engineering/bug-fix/`，模型可自动调用。流程：

1. 前提：Task 已由用户指定并认领。bug-fix 只检查这一前提，不实现认领流程（认领规则在 `immutable-spec`，见 S0009）。
2. 只读复现。项目里有 `verify-<app>` 时优先用它，其次用测试、脚本或直接操作真实应用。记录复现命令和输出。
3. 无法复现：说明原因、尝试过的路径和缺少的条件，然后停止。不因为用户提出就强行修复。后续去向由用户决定。
4. 已复现：判定复杂度，把结果和依据写入 Task。满足任意一条即为复杂：
   - 根因跨越模块边界；
   - 涉及数据、迁移或并发；
   - 需要先做设计决策；
   - 验收标准无法用一句话写清。

   判定后分两条路：
   - 复杂：用 lite spec 模板（S0002）建 spec，按 `spec-design` 简化版（S0007）走两个关口。关口 A 确认复现结果和根因，关口 B 确认修复方案和验证标准。未安装 `immutable-spec` 时，把复现记录、根因、方案和验证标准写入 Task，并提示可以改用 spec 跟踪。
   - 简单：直接修复，复现命令与先失败后通过的输出写入 Task 或 PR。用户可以随时把它升级为复杂。
5. 用证据定位根因：列出假设，逐个排除，每一步要有运行证据。证据否定了某个假设，就回滚它带来的改动。
6. 失败用例先于修复提交。
7. 在复现的同一界面上验证。

### Constraints

- 独立安装。`tdd`、`immutable-spec`、`spec-design` 都是可选输入。
- 只合入证据支持的最小改动。

### Non-goals

- 运行时诊断、trace 分析。
- PR 合并流程。

## 4. Test and Acceptance Criteria

行为类 TC 用 S0008 的 eval 用例验证，用例放在 `evals/bug-fix/`，由 `npm run eval:bug-fix` 运行，用例 ID 写在 TC 中。用例先经用户审核再运行。结构类 TC 用 `tests/bug-fix/run.sh` 检查，该脚本不随 skill 分发。试运行类 TC（TC-8、TC-9）需要用户指定的真实项目和 bug，在那之前无法执行。

- TC-1 frontmatter 合法，name 与目录一致，没有 `disable-model-invocation`（模型可调用），SKILL.md 链接的本地文件都存在。
  method: command: `tests/bug-fix/run.sh structure`
- TC-2 eval 用例 `bug-fix.unreproducible-stops`：报告在现有条件下无法复现，用户要求修复。agent 停止，说明无法复现、尝试过的路径和缺少的条件，没有修改产品代码和测试。
  method: command: `npm run eval:bug-fix`
- TC-3 eval 用例 `bug-fix.simple-red-before-fix`：对可复现的简单 bug，git 历史中失败用例先于修复提交；HEAD 上同一入口（复现用的 CLI 命令）输出正确；Task 中记录了复现命令和先失败后通过的输出。
  method: command: 同 TC-2
- TC-4 复杂度判定的结果和理由写入 Task、PR 或 spec：用例 `bug-fix.simple-red-before-fix` 的 Task 记录“简单”，用例 `bug-fix.complex-lite-spec` 的 Task 或 spec 记录“复杂”，并给出依据。
  method: command: 同 TC-2
- TC-5 SKILL.md 内联的 bugfix 门槛块与 `immutable-spec` 逐字一致；一致性检查和它的变更测试都通过。
  method: command: `tests/bug-fix/run.sh gates && scripts/check-skill-consistency.py && tests/consistency/run.sh`
- TC-6 `agents/openai.yaml` 存在且没有禁止隐式调用；README 在 Model-invoked 下有本 skill 的条目，目录树列出 `bug-fix/`。
  method: command: `tests/bug-fix/run.sh install`
- TC-7 eval 用例 `bug-fix.complex-lite-spec`：对涉及数据、跨模块的 bug，agent 用 lite spec 模板建 draft spec，记录真实运行得到的复现输出和 `file:line` 根因，停在关口 A 请用户确认，没有修改产品代码和数据，没有自己记录关口通过。
  method: command: 同 TC-2
- TC-8 真实可复现 bug 试运行：试运行项目的 git 历史中失败检查的提交早于修复提交，Task 或 PR 中有复现命令和先失败后通过的输出。
  method: command: 在用户指定的试运行项目中运行 `git log --reverse --stat <base>..HEAD`，在失败检查提交上运行复现命令确认失败、在 HEAD 上运行确认通过，并核对 Task 或 PR 中的记录
- TC-9 真实不可复现报告试运行：skill 停止后没有产品代码改动，Task 中有原因、尝试过的路径和缺少的条件。
  method: command: 在用户指定的试运行项目中运行 `git status --porcelain` 与 `git log --stat <base>..HEAD`，并核对 Task 中的记录
- 通过标准：全部 `pass`。eval 用例的 `minPassRate` 在 `evals/bug-fix/case-review.md` 中说明。
